# 第一阶段：文字提取与校准

## 检查和文字清单

PPTX 先检查画布和实际 slide 关系。图片不一定叫 `image1.png`；从每张 slide 的关系解析嵌入资源，记录 srcRect、xfrm、旋转、翻转及祖先组变换。保留已有正确的原生文字。

使用视觉阅读与当前可用 OCR 建立清单，OCR 仅提供候选。逐项核对大小写、希腊字母、连接号、上下标、单位及混合颜色。拿不准的字符记录疑点，不凭学科常识改写。源图文字错误属于图像内容，除非用户要求校订，否则保留并另行指出。

每条文字记录：稳定 ID、逻辑标签 ID、原文、`glyph_bbox_xywh`、`mask_bbox_xywh`、字体/字号/字重/颜色/字距、混合格式 runs、背景恢复方式、邻近保护对象和不确定项。坐标来自当前图测量，明确单位。逐行校准时可用多个文本框，但同一逻辑标签应分组；不要将整段拆成逐字对象。

## 去掉底图中的文字

遮罩目标是原文字字形，不是标签周围的大矩形：

- 白色平坦区域可用局部无边线覆盖形。
- 非白色平坦区域从不含文字/轮廓的邻近像素估计底色。
- 渐变区域可用拟合的原生渐变或局部背景恢复，禁止默认补白。
- 文字压在线条/组织上时，先记录被遮结构，恢复背景与路线；必要时用精细字形遮罩，不将邻近引线一起擦掉。

遮罩余量依据当前分辨率、抗锯齿和邻近对象决定。特别检查 `g/p/q/y` 下伸部、斜体外伸和特殊符号。没有必要把文字版底图强制矢量化。

阶段1工作副本可保留原始媒体，以证明背景没有被无意替换。若确实恢复了背景，则保存原始媒体和恢复记录，不再声称其字节不变。

## 原生文字校准

- 尽可能匹配源字体；字体不可用时说明替代，按实际字形宽度验证。
- 使用字形边界/基线定位，不把截图中字形顶点直接当作文本框顶点。
- 先校准字体、字号和字距，再校准文本框/行距。不要任意拉伸整个字形来凑宽。
- 明确文本框边距、自动换行与 autofit 行为，保留原换行。混色文字使用原生 runs。
- 输出后在目标应用渲染。字体测量是初始估计，不能代替 PowerPoint 实际字形布局。

逐区检查底图文字是否仍露出、是否出现白块、文本是否裁切、单词是否变色或断行，最后看整页比例与阅读顺序。

## 阶段确认与冻结

交付文字版 PPTX 与其实际渲染预览。默认两阶段评审中，用户确认的是这一具体文件的文字与排版。记录哈希、确认消息依据及确认范围；不能只记录模糊的“已确认”。已有连续运行授权时不重复询问。

第二阶段保留整个原生文字节点：runs、字体、段落、边距、换行、字距、位置及祖先组变换。优先复制原生对象；若不得不重建，重新核对有效位置和外观，不能宣称 XML 精确保留。

可用辅助脚本做原生文字回归检查：

```text
python <skill>/scripts/pptx_audit.py compare-text <approved-stage1.pptx> <stage2.pptx> --name-prefix TEXT_ --out <audit.json>
```

省略 `--name-prefix` 检查所有含文本的原生形状。若 ID 合理变化而名称稳定且唯一，可选 `--match-by name`。差异需要解释或修复，不能直接绕过。此检查不覆盖位图文字，也不验证字体实际渲染。
